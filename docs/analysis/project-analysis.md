## 레거시 코드 스멜 (Legacy Code Smells)

| # | 스멜 | 설명 |
|---|------|------|
| 1 | **God Function** | `main()` 하나가 입력·파싱·검증·변환·출력을 모두 처리함 |
| 2 | **매직 넘버 (Magic Numbers)** | `3.28084`, `1.09361`이 이름 없는 리터럴로 여러 곳에 반복됨 |
| 3 | **DRY 위반** | 동일 변환 계수가 입력 역변환(16–21행)과 출력 변환(27–28행)에 중복 |
| 4 | **확장 불가능한 분기** | `if/elif` 체인으로 단위 추가 시 기존 코드 수정 필요 (OCP 위반) |
| 5 | **클래스/추상화 부재** | SRP·OCP를 위한 클래스·인터페이스 없이 절차형 스크립트 |
| 6 | **관심사 미분리** | I/O, 비즈니스 로직, 출력 포맷이 한 함수에 혼재 |
| 7 | **검증 불완전** | 형식·숫자·알 수 없는 단위만 검사, **음수 입력 검증 없음** |
| 8 | **출력 정밀도 미처리** | PRD 예시(`8.2 feet`)와 달리 raw float 그대로 출력 |
| 9 | **자기 단위 변환 출력** | `meter:2.5` 입력 시 `2.5 meter = 2.5 meter`도 함께 출력 |
| 10 | **테스트 부재** | 변환 정확성·입력 검증을 검증하는 TC 없음 |
| 11 | **설정 하드코딩** | 변환 비율이 코드에 고정, 외부 설정 파일 미사용 |
| 12 | **확장 포인트 없음** | 동적 단위 등록·출력 포맷 선택을 위한 구조 없음 |

## 요약

현재 `UnitConverter.py`는 **Activity 1단계(문제 코드 분석)용 레거시 스켈레톤** 수준이다. 핵심 변환 계수와 기본 입출력만 있고, PRD의 설계 원칙(OCP/SRP), 품질(입력 검증·TC), 추가 기능(설정 외부화·동적 등록·출력 포맷)은 대부분 미구현이다.

### 우선 구현 대상

1. **구조** — OCP/SRP를 위한 클래스·인터페이스 분리
2. **품질** — 음수 검증 + 단위 변환 TC
3. **확장성** — 설정 외부화, 동적 단위 등록, 출력 포맷 선택
